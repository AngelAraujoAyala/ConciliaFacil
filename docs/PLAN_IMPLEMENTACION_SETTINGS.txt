OBJETIVO
--------
Hacer funcional el apartado completo de Settings (/home/configuracion), con
persistencia real, sincronizacion entre Supabase Auth y backend Nest/Prisma,
y flujos de billing, exportacion y eliminacion de cuenta.


================================================================================
1. ESTADO ACTUAL (DIAGNOSTICO)
================================================================================

Tab              | Estado actual | Persistencia real
-----------------|---------------|--------------------------------------------------
Perfil           | ~70%          | Supabase Auth (full_name, phone en store sin UI)
Facturacion      | ~50%          | GET /users/me (lectura); portal Stripe hardcodeado
Seguridad        | ~80%          | Supabase Auth (solo usuarios email/password)
Preferencias     | ~10%          | Solo Zustand en memoria (se pierde al recargar)
Zona de peligro  | ~15%          | Export stub; RPC delete_user_account inexistente

Conclusion: la UI esta lista. Falta cerrar persistencia, sincronizacion y
flujos criticos de billing/export/delete.


================================================================================
2. PRINCIPIOS DE ARQUITECTURA
================================================================================

2.1 Separar identidad vs datos de negocio
    - Supabase Auth: email, contraseña, user_metadata (nombre, telefono).
    - Nest + Prisma: plan, uso, empresas, conciliaciones, preferencias.

2.2 Una fuente de verdad por dato
    - No duplicar full_name en Prisma salvo necesidad de reportes offline.
    - Preferencias -> tabla/columna en BD, no solo Zustand.

2.3 React Query para datos remotos; Zustand para UI state
    - useGetProfile ya existe -> extender con mutations.
    - useSettingsStore -> tab activa, drafts locales, feedback transitorio.

2.4 Settings con URL
    - /home/configuracion/:tab para deep links, back/forward y compartir.

--- 5A: EXPORTAR DATOS ---

  - Incluir: perfil, empresas, conciliaciones (metadata), plan, fechas.
  - Rate limit: 1 export por hora.

--- 5B: ELIMINAR CUENTA ---

Flujo recomendado (orden importa):
  1. Cancelar suscripcion Stripe (si existe)
  2. Borrar datos en Prisma (cascade: conciliaciones, empresas)
  3. Borrar usuario en Supabase Auth (Admin API / service_role)
  4. signOut() + clearAllApplicationData()

Opciones de implementacion:
  A) Nest DELETE /users/me con SUPABASE_SERVICE_ROLE_KEY (RECOMENDADO)
  B) Supabase Edge Function con service_role
  C) RPC PostgreSQL (no borra auth.users sin Admin API)

Paso 5B.1 - Endpoint DELETE /api/users/me
  - Orquestar Stripe + Prisma + Supabase Admin.

Paso 5B.2 - DangerTab frontend
  - Reemplazar supabase.rpc("delete_user_account") por llamada al API.
  - No cerrar modal si falla; mostrar error especifico.
  - Reemplazar alert() por toast.

Criterio de done Fase 5:
  [ ] Export incluye datos de negocio reales
  [ ] Delete elimina todo y redirige a login

7. RIESGOS Y MITIGACIONES
================================================================================

Riesgo                              | Mitigacion
------------------------------------|------------------------------------------
Limites de plan desincronizados     | Single source of truth en backend
Delete sin cancelar Stripe          | Cancelar subscription antes de borrar
signInWithPassword altera sesion    | Evaluar reauthenticate o reset por email
Preferencias solo en localStorage   | Siempre persistir en BD en v1
Usuarios OAuth sin contraseña       | Branch UI por proveedor de auth
RPC delete_user_account inexistente | Implementar DELETE /users/me en Nest
